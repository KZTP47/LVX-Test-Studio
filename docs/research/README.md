# Agent orchestration research

These reports examine the actual pinned source of all supplied repository references, the resolved LinkedIn destination and the complete recovered public video transcript. They guided LVX's implementation; this is not a claim that an entire external orchestration engine was copied or embedded.

| Reference | Detailed report | Main decision |
|---|---|---|
| Openrig | [Source analysis](openrig.md) | Preserve native sessions and durable events; build an editable Windows-friendly graph rather than transplant its Unix/tmux runtime or instruction hooks. |
| Buzz | [Buzz and Traycer](buzz-traycer.md) | Use session-affine queues and generation fences; retain refusal/limit states rather than treating every finished stream as success. |
| Traycer | [Buzz and Traycer](buzz-traycer.md) | Keep communication visible and distinguish actual inbound/outbound capability; public source does not include every host-side component. |
| Herdr / YouTube | [Full transcript analysis](video.md) · [Initial fleet comparison](fleet-nexus.md) | Herdr is the terminal wrapper in this demonstration; OpenRig coordinates the agents. Distinguish observed progress from ceremony, scoped context and inherited guidance. Full transcript recovered after the initial fetch limitation; no complete audiovisual inspection claimed. |
| LinkedIn / SWE-AF | [Fleet and Nexus comparison](fleet-nexus.md) | The safety redirect resolves to Agent-Field/SWE-AF. Keep executable checks and reviewer evidence separate from agents' own success claims. |
| Nexus Harness | [Fleet and Nexus comparison](fleet-nexus.md) | Preserve the visual board and multi-provider idea; avoid unsolicited standing rules, busy-agent steering, clipped peer context and delivery acknowledgements before actual delivery. |

The JSON companions record repository commits or the transcript fingerprint, with concrete source/timestamp anchors. The earlier fleet report retains its initial fetch limitation; `video.md` and `video.json` supersede that limitation using the complete recovered transcript. Reports describe missing components and limitations explicitly. Available Nexus code was obtained as a clean source checkout; no project memory vault, authentication files or private conversations were accessed. Identified mechanisms are plausible risks, not experimental proof of what caused earlier poor model output.

The maintained implementation uses original LVX code. The pinned checkouts remain ignored research material under `output/research`; their install scripts were not executed. Third-party license findings are recorded per report, including unresolved Nexus licensing. No Nexus implementation source was copied.
