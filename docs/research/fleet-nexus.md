# Fleet, Herdr and Nexus research — 2026-10-25

The useful combination for LVX is persistent native agent sessions, visible directed communication, and optional engineering recipes. The graph should describe what the agents may communicate and what they are doing. It should not quietly replace a provider's normal instructions with a mandatory orchestration framework. This is a design conclusion from static source inspection, not a measured claim that any framework improves model quality.

## SWE-AF: useful engineering mechanisms, expensive defaults to expose

SWE-AF runs explicit planning roles rather than relying on agents chatting until they agree. `run_product_manager`, `run_architect`, `run_tech_lead` and `run_sprint_planner` persist separate planning artifacts. Issue execution combines a dependency DAG, per-issue work, review, integration and final verification. This makes outcome provenance easier to represent as artifacts attached to graph nodes. [Planning implementation](https://github.com/Agent-Field/SWE-AF/blob/4d3dfe719e5ce9e2e8cd454722295bbe6512542f/swe_af/reasoners/pipeline.py#L529).

Its inner coding loop has two paths: the normal path calls a coder and then a reviewer; only issues flagged by sprint-planner guidance receive QA and reviewer calls in parallel followed by a synthesizer. The middle loop can adapt a failing issue; the outer loop can restructure the DAG. Therefore “a fleet ran” does not establish that an independent test agent ran for every task. If review is repeatedly nonblocking and changed files exist, the loop may accept `COMPLETED_WITH_DEBT` after getting stuck or exhausting iterations. LVX should preserve this distinction visibly, alongside unmet acceptance criteria and actual check results. [Coding loop and debt handling](https://github.com/Agent-Field/SWE-AF/blob/4d3dfe719e5ce9e2e8cd454722295bbe6512542f/swe_af/execution/coding_loop.py#L515).

`_execute_level` bounds parallel issue work using an asyncio semaphore and collects independent results with `gather(return_exceptions=True)`. Defaults include three concurrent issues, five coding iterations and bounded replanning/fixing; learning is disabled by default. A production recipe should expose these settings and cost implications rather than silently creating many agents. Mechanical Git operations have a deterministic fast path, leaving conflict resolution to an agent when required. [Scheduler](https://github.com/Agent-Field/SWE-AF/blob/4d3dfe719e5ce9e2e8cd454722295bbe6512542f/swe_af/execution/dag_executor.py#L1270), [configuration](https://github.com/Agent-Field/SWE-AF/blob/4d3dfe719e5ce9e2e8cd454722295bbe6512542f/swe_af/execution/schemas.py#L980).

Task checkpoints and native conversational continuity are different. SWE-AF stores a DAG checkpoint and build-scoped per-issue iteration state, and passes slim artifact paths for agents to read. Optional cross-issue context contains conventions, failure/bug patterns and completed-dependency interfaces. The inspected Codex adapter starts `codex exec --json`, appends a structured-output contract and returns an empty session ID; this path does not implement the same persistent thread as Nexus's app-server adapter. Do not extend that observation to every SWE-AF runtime. The checkpoint writer uses direct JSON writes; this inspection does not establish atomic recovery under a crash during the write. LVX should use transactional events or atomic replace plus validated snapshots. [Checkpoints](https://github.com/Agent-Field/SWE-AF/blob/4d3dfe719e5ce9e2e8cd454722295bbe6512542f/swe_af/execution/dag_executor.py#L824), [iteration/context helpers](https://github.com/Agent-Field/SWE-AF/blob/4d3dfe719e5ce9e2e8cd454722295bbe6512542f/swe_af/execution/coding_loop.py#L47), [Codex adapter](https://github.com/Agent-Field/SWE-AF/blob/4d3dfe719e5ce9e2e8cd454722295bbe6512542f/swe_af/runtime/codex_harness_patch.py#L247).

Permissions and provider support need explicit handling. The Codex patch maps `permission_mode=auto` to dangerous approval/sandbox bypass; its fallback uses workspace-write. Its native runtime allowlist contains Claude, Codex, OpenCode, AForge and Command Code, not native Gemini CLI. Support for Google model IDs through another runtime does not prove use of the user's Gemini subscription. SWE-AF also enables ready-for-review PR creation and CI checking by default. Adopt its bounded CI watch/fix design only as an explicitly selected recipe; the visual session board must not inherit publication side effects. [Provider mapping](https://github.com/Agent-Field/SWE-AF/blob/4d3dfe719e5ce9e2e8cd454722295bbe6512542f/swe_af/runtime/providers.py#L5), [CI gate](https://github.com/Agent-Field/SWE-AF/blob/4d3dfe719e5ce9e2e8cd454722295bbe6512542f/swe_af/app.py#L316).

## Herdr: faithful sessions, cautious lifecycle detection

Herdr's distinctive contribution is retaining real terminal sessions while exposing agent operations through a CLI/socket API. Its prompt path validates agent identity, snapshots event sequence, admits input, then requires observed working or blocked activity when the agent was not already working. A stalled prompt produces a distinct error. Recognized permission/question dialogs reject ordinary prompts before input is written; test source explicitly asserts this behavior. These are better primitives for a truthful node status than “send returned, therefore the job started.” [Prompt wait](https://github.com/herdrdev/herdr/blob/5608de0608918aba2f9d501e7793b984a0ca9cfa/src/api/wait.rs#L177), [blocked validation](https://github.com/herdrdev/herdr/blob/5608de0608918aba2f9d501e7793b984a0ca9cfa/src/app/api/agents.rs#L138).

The remaining limit matters: a lifecycle-state wait is not a turn-correlated completion receipt. If an agent was already working, its existing turn can satisfy a wait. Screen-derived status may miss an unfamiliar dialog. Current [agent documentation](https://herdr.dev/docs/agents/) calls Gemini CLI state-only and less tested, and explains that a status signal must never be interpreted as approval. LVX should prefer protocol events with thread/turn IDs, label inferred terminal status, and show unknown or blocked states honestly. A timeout can mean the send outcome is uncertain, so blind retry may duplicate work.

Persistence also needs honest language: a detached client leaves the server and agents running; restarting the server or machine does not preserve arbitrary original processes. Supported provider conversations can be resumed with validated provider-specific commands. Saved layouts, provider references and optional terminal history are separate concerns. Herdr keeps history off by default because terminal output can contain sensitive material. LVX should persist its own event records and session IDs without scraping private provider histories. [Resume planner](https://github.com/herdrdev/herdr/blob/5608de0608918aba2f9d501e7793b984a0ca9cfa/src/agent_resume.rs#L199), [persistence module](https://github.com/herdrdev/herdr/blob/5608de0608918aba2f9d501e7793b984a0ca9cfa/src/persist.rs#L1), [restart distinctions](https://herdr.dev/docs/session-state/).

## Nexus: retain its strong primitives, avoid its hidden policy coupling

The public Nexus snapshot already has a substantial persistent v3 session layer. Codex uses app-server with thread/start, thread/resume, turn/start and turn/steer. Claude has a persistent stream-json process and native resume IDs. Gemini uses ACP initialization and optional session/load, with queued messages because ACP does not provide its mid-turn steer path. Stable agent seats are separate from replaceable provider session IDs. These details refute a blanket explanation that Nexus always starts a fresh agent or clips all native context on each reply. [Codex](https://github.com/KZTP47/nexus-harness/blob/d5b799b80e4ade5b22cb0377e085ddc96c65c1d7/src/our_harness/agent_runtime/codex_session.py#L36), [Claude](https://github.com/KZTP47/nexus-harness/blob/d5b799b80e4ade5b22cb0377e085ddc96c65c1d7/src/our_harness/agent_runtime/claude_session.py#L54), [ACP](https://github.com/KZTP47/nexus-harness/blob/d5b799b80e4ade5b22cb0377e085ddc96c65c1d7/src/our_harness/agent_runtime/acp_session.py#L55).

There are nevertheless concrete ways an orchestration layer can interfere:

- `TeamRun.start` always adds `STANDING_RULES`. Codex receives them as developer instructions and Claude through an appended system-prompt file. Rules include a universal requirement that web pages work by double-clicking `index.html` via `file://`, plus tool and report constraints. This can change an ordinary framework-based project's implementation direction. The rule's presence is proven; its role in the user's observed quality loss is not. [Rules and injection](https://github.com/KZTP47/nexus-harness/blob/d5b799b80e4ade5b22cb0377e085ddc96c65c1d7/src/our_harness/agent_runtime/team.py#L26).
- Busy sessions automatically steer when the adapter supports it. A peer message can alter active work immediately rather than waiting as an inbox item. LVX should default to queued delivery at a turn boundary and make steering deliberate. [Send behavior](https://github.com/KZTP47/nexus-harness/blob/d5b799b80e4ade5b22cb0377e085ddc96c65c1d7/src/our_harness/agent_runtime/base.py#L91).
- `_deliver` records unavailable/failed outcomes but still calls `mark_delivered` for the message as a whole. Broadcast delivery has no durable per-recipient acknowledgement in this path. `Mailbox.send` also slices message text at 20,000 characters. LVX should retain pending recipients, reject or explicitly file-back oversized messages, and never silently retire a failed delivery. These are static code findings, not runtime reproductions. [Delivery](https://github.com/KZTP47/nexus-harness/blob/d5b799b80e4ade5b22cb0377e085ddc96c65c1d7/src/our_harness/agent_runtime/team.py#L427), [mailbox](https://github.com/KZTP47/nexus-harness/blob/d5b799b80e4ade5b22cb0377e085ddc96c65c1d7/src/our_harness/agent_runtime/mailbox.py#L88).
- Requested worktree isolation falls back to the shared project folder when creation fails. A warning exists, but other agents can now share write paths. LVX should stop that agent's writable launch until isolation is repaired or the user deliberately changes the mode. [Work directory selection](https://github.com/KZTP47/nexus-harness/blob/d5b799b80e4ade5b22cb0377e085ddc96c65c1d7/src/our_harness/agent_runtime/team.py#L186).
- The older collaboration engine requires an action-schema answer and projects long history using complete recent turns plus a semantic summary. These are disclosed code policies, but they are not equivalent to the v3 native session layer. LVX should separate transport from such optional context transformations. [Legacy policy](https://github.com/KZTP47/nexus-harness/blob/d5b799b80e4ade5b22cb0377e085ddc96c65c1d7/src/our_harness/chat.py#L245).

Nexus's positive ideas remain useful as independent designs: stable addresses, durable task ownership, closure reasons, path leases and explicit teammate attribution that grants no permissions. Its inspected project licensing is unresolved, so this report recommends independently implementing the concepts rather than copying its source.

## Concrete LVX contract

The session board should store nodes with stable agent ID, provider, explicit model or provider default, cwd, thread/session reference, capability flags and permission mode. A node opens a conversation/event panel. Directed edges allow specific sender-to-recipient messages and show pending, admitted, started, completed, failed or uncertain outcomes. Protocol support should be negotiated for Codex, Claude and Gemini separately. A signed-in CLI may be usable, blocked, rate-limited or unsupported for a requested model; “subscription” is not a guaranteed entitlement.

Keep four concerns separate: node/edge topology; native provider transport; project task ownership/artifacts; optional plan/review/QA recipes. The user must be able to inspect exactly what text and policy a recipe adds. A short project-purpose/task-parent chain can restore context after compaction, while original user instructions remain authoritative. A peer can ask for work, propose changes or provide evidence; it cannot grant the user's permissions.

For restart safety, persist append-only project events and atomically written validated snapshots. Track message recipients and attempts durably. Preserve uncertain submission states for reconciliation; automatic replay needs provider-supported idempotency or evidence that the previous attempt never started. Resume failures should show a visible new-session decision rather than pretending continuity. Retain transcript material only under an explicit project-local policy; provider private chats and other project vaults are unnecessary.

Recommended acceptance cases are observable: a failed recipient remains pending after restart; a broadcast can show one acknowledged and one pending recipient; a blocked agent receives no ordinary prompt; a long message cannot silently lose its tail; a resume failure is visible; an isolated-worktree launch never falls back to shared writes; completed-with-debt stays distinct from verified success; default free-form sessions add no unseen product rules. Finally compare direct CLI and LVX on the same repository commit, provider/model/effort, permission mapping, prompt and acceptance checks. A prompt diff and actual resulting behavior are stronger evidence about quality than a larger graph or more review roles.
