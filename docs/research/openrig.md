# OpenRig: source review for the LVX agent studio

Reviewed on 2026-10-25. Repository: [mvschwarz/openrig](https://github.com/mvschwarz/openrig). The read-only checkout is pinned to **9bb29d38819bdd2bbe5b8527ce057db606c82cf9**, authored 2026-10-24, subject `fix: renew owned Codex plugin content approvals on upgrade (#1948)`. All links below identify that exact commit. This is static source research: no dependency installation, repository scripts, agent launches, provider logins, private chats or credential files were used. Tests mentioned below were read, not run. No claim of model-quality parity or account entitlement follows from this review.

## Decision

OpenRig is a strong reference for durable native agent sessions and visible peer collaboration. Its engine runs ordinary interactive provider CLIs inside tmux, rather than substituting a generic model chat loop. However, its full managed launch path changes guidance, hooks, launch settings, writable directories and sometimes compaction behavior. LVX should implement a smaller native CLI session layer and borrow its identity, event, delivery and graph concepts. Adopt the local CLI session as the authority; make orchestration observable and optional.

For the planned LVX implementation, the appropriate first slice is one persistent native conversation per visible node, direct CLI turn/resume, full provider output retained, explicitly addressed peer messages delivered after idle, and distinct transport and quality outcomes. The evidence supports these architectural choices; it does not establish current provider command compatibility on the user's machine.

## Architecture and native-provider contract

The daemon mounts Hono HTTP areas for rigs, sessions, events, transcripts, transport and activity; a terminal WebSocket is registered only when the experimental web UI is enabled. This makes the UI a projection/control surface rather than the owner of agent execution. SQLite uses WAL and foreign keys. `EventBus.persistWithinTransaction` inserts a sequenced event; `withNotifyEnvelope` requires registration of the exact persisted tokens before commit, then drains committed rows. These are useful patterns for a studio whose browser may reconnect without restarting agents. Evidence: [server.ts, route wiring L735–779](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/server.ts#L735-L779), [createDb L7–13](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/db/connection.ts#L7-L13), [EventBus L53–145](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/event-bus.ts#L53-L145).

`RuntimeAdapter` separates resource projection, startup delivery, launch and readiness. `NodeBinding` includes cwd, model, effort, native permission posture and launch generation. Its result distinguishes attention gates, missing conversations, unproven resumes, mismatched IDs and pending fork identity. LVX should preserve that distinction instead of mapping every nonzero result to a fresh retry. Evidence: [runtime-adapter.ts L10–47, L85–159, L201–230](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/runtime-adapter.ts#L10-L47).

Claude uses native `--session-id`, `--resume` and `--fork-session`; fork gets its own generated ID. Optional model, effort and Advisor choices are emitted as CLI flags, and omitted model/effort stays omitted. Codex uses native interactive `codex`, `codex resume` and `codex fork`, with shared launch preparation for model/effort across paths. Its resume launch is verified before the saved ID is accepted. This demonstrates a subscription-CLI integration shape; it does not prove billing terms, provider entitlements or quality parity. Evidence: [ClaudeCodeAdapter.launchHarness L290–365](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/claude-code-adapter.ts#L290-L365), [CodexRuntimeAdapter.launchHarness L728–825](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/codex-runtime-adapter.ts#L728-L825), [prepareLaunch L863–944](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/codex-runtime-adapter.ts#L863-L944).

Gemini is **not a built-in adapter** at this commit: the explicit set is Claude Code, Codex, Pi, OMP, terminal and stub. A community preset can launch another harness, but its default readiness proves only a non-shell foreground process, it projects no resources, and it refuses fork. Reported or assigned conversation names carry weaker provenance than observed native identity. Thus a Gemini preset is an extension route, not tested native Gemini parity. LVX needs its own capability-tested Gemini adapter. Evidence: [built-in-runtimes.ts L1–8](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/built-in-runtimes.ts#L1-L8), [CommunityHarnessRuntimeAdapter L31–165](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/community-harness-runtime-adapter.ts#L31-L165).

## Communication, state and recovery

Peer communication is a real input effect into the receiving native session. `TmuxAdapter.sendText` stages text in a unique file/buffer, uses bracketed paste with raw LF preservation, and leaves Enter as a separate effect. This avoids interpreting newlines as many prompts. `wrapPaneEnvelope` renders sender, recipient, timestamp, optional sender generation and reply guidance. Broadcast scope is explicit. The plain terminal path omits the agent envelope because a shell could execute its header as commands. LVX should keep explicit peer attribution, preserve the entire body and avoid unmarked model-generated summaries. Evidence: [TmuxAdapter.sendText L851–908](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/tmux.ts#L851-L908), [wrapPaneEnvelope L94–129](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/lib/pane-envelope.ts#L94-L129), [SessionTransport.send L2229–2237](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/session-transport.ts#L2229-L2237).

Delivery guards serialize machine input with lifecycle changes and bind it to the selected occupant. A particularly useful fixture creates a human draft after buffer loading and another between paste and Enter; it expects retained delivery in the first case and refuses the changed draft in the second. This is a real tmux fixture with simulated provider composers; it is skipped on win32 and explicitly disclaims live-model proof. LVX's direct structured CLI transport may avoid some screen parsing, but it still needs a single input owner and generation checks when a node resumes or changes provider. Evidence: [draft-aware-delivery-native.test.ts L23–27, L61–109](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/test/draft-aware-delivery-native.test.ts#L23-L109).

**Important difference to adopt deliberately:** ordinary OpenRig sends proceed while target state is busy or unknown, with an advisory. Only positively identified interactive prompts refuse by default; an explicit audited override can drive those prompts. This favors availability, but peer messages can interfere with current reasoning. LVX should default to an idle mailbox and expose explicit human steering as a separate action. Unknown state should remain visible instead of masquerading as idle. Evidence: [SessionTransport.sendUnguarded L2878–2982](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/session-transport.ts#L2878-L2982).

`verify` checks terminal evidence, not reasoning quality or work acceptance. After paste and Enter succeed, capture failure becomes `rendered-unconfirmed`, not a false send failure. Verification can compare rendered envelope occurrences, or, when enabled, exact pre-Enter input, empty post-Enter composer and same process. None proves the agent understood the peer, completed its work or passed a review. LVX should show `queued → admitted → started → completed/blocked` for execution and store delivery receipts separately from review/acceptance. Evidence: [SessionTransport verification L3124–3171](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/session-transport.ts#L3124-L3171).

The outbox has pending, sending, delivered, failed, indeterminate, retained and retired states. CAS transitions avoid overwriting already resolved states. Crash recovery converts abandoned sending claims to indeterminate without blind retransmission. **Caveat:** `claimForDelivery` explicitly permits a previously indeterminate row to be claimed again; this is not universal exactly-once delivery. LVX should store a message ID/body hash/recipient generation and distinguish a known pre-write failure from an unknown post-write outcome. Retry only with effect knowledge or explicit review. Evidence: [OutboxHandler L17–20, L264–321, L362–378](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/outbox-handler.ts#L264-L378), [outbox-handler tests L86–135](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/test/outbox-handler.test.ts#L86-L135).

Cancellation is phase aware: an aborted caller waiting before input begins must never write later; after input may have begun, the result remains attempted/written. Committed queue deliveries do not inherit the browser caller's cancellation. Stopping a managed seat is a separate lifecycle action with a reason, lease and optional expected node/session tuple. Claimed/adopted sessions are refused by that stop path. LVX should similarly separate cancel queued message, interrupt active turn, stop owned process and close UI panel. Evidence: [SendOpts.signal L1588–1596](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/session-transport.ts#L1588-L1596), [SeatLifecycleService.stopSeat L853–944](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/seat-lifecycle-service.ts#L853-L944).

SSE replay subscribes before reading, fixes a high-water sequence, reads pages of 500, drains buffered arrivals, deduplicates by sequence and supports Last-Event-ID. This is a sound recovery pattern for graph state. A potential scaling concern from static inspection is that the live buffer is unbounded during replay and live writes are not awaited. The web hub initially requests `/api/events` without a replay bound, although the server supports one. These are concerns to test, not measured regressions. LVX should use a bounded initial replay plus snapshot sequence and explicit resync when a consumer falls behind. Evidence: [eventsRoute L15–93](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/routes/events.ts#L15-L93), [TopologyEventHub L16–97](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/ui/src/lib/topology-events.ts#L16-L97).

## Native quality: what to preserve and what to omit

Unmodified provider binaries do not imply unchanged operating context. Codex startup can merge AGENTS.md and install skills. `prepareLaunch` applies managed config/hooks, can install the selected core plugin, emits sandbox/network/queue-directory flags and can add `--no-daemon`. Claude startup merges guidance, installs skills and provisions telemetry; native launch selects a permission mode. Managed Claude compaction can disable the native idle-compaction setting. These all affect effective agent behavior even though the vendor CLI remains native. Evidence: [Codex deliverStartup L674–725](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/codex-runtime-adapter.ts#L674-L725), [Codex prepareLaunch L863–939](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/codex-runtime-adapter.ts#L863-L939), [Claude deliverStartup L190–241](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/claude-code-adapter.ts#L190-L241), [operationalLaunchArgs L63–103](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/kernel-authority.ts#L63-L103).

Claude launch additions deserve special attention: an appended system prompt is additive, but selecting an agent whose prompt is nonempty is reported as replacing Claude's default main-agent system prompt. The source also tracks changed prompt text whose application may remain pending until compaction/new conversation depending on Claude version. LVX should not synthesize a main-agent role or silently replace system prompts. Record immutable launch metadata, exact additions and provider/version provenance. Expose optional user-authored roles as an explicit advanced choice with their actual semantics. Evidence: [SeatLaunchAdditionsReport L247–261](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/seat-launch-additions.ts#L247-L261), [systemPromptPendingNote L378–387](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/seat-launch-additions.ts#L378-L387).

OpenRig's context composer has one valuable quality property: runtime-specific dependency closure fails loudly and token budgets report overage/drop candidates instead of truncating. This is stronger than an arbitrary short summary handoff. It also means large context may remain large; the existence of a budget report does not prove efficient or high-quality model use. LVX should retain exact original task and full provider output, show budget warnings, and let users opt into visible excerpts rather than silently compressing peers. Evidence: [composeProfile L170–220](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/domain/context-packs/profile-composer.ts#L170-L220).

Permission defaults also differ from an untouched CLI: Claude's floor selects `acceptEdits`; Codex's no-profile floor selects workspace-write; explicit full bypass adds danger-full-access/never for Codex. Kernel allowances are broader again. This is implementation evidence, not an allegation of unsafe behavior. LVX's initial native adapter should preserve the selected native policy and surface any launch override, never add YOLO to make a demo work. Evidence: [claudePostureFlag/codexPostureArg L36–81](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/yolo-mode.ts#L36-L81), [kernel authority L9–22](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/daemon/src/adapters/kernel-authority.ts#L9-L22).

## Visual studio mechanisms

OpenRig already contains the key visual ingredients: React Flow rig/pod/agent nodes, runtime/model badges, activity states, context/token metrics, directional queue edges, terminal preview and native terminal launch. `HostMultiRigGraph` uses backend graph projections and activity hooks, then renders custom nodes/edges. Its source sets `nodesDraggable={false}`, so its graph is an observer/navigation surface rather than an editable agent wiring canvas. LVX should distinguish visual collaboration links from executable routing rules and make each relationship inspectable. Evidence: [HostMultiRigGraph L66–80, L270–295, L354–365](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/ui/src/components/topology/HostMultiRigGraph.tsx#L66-L80), [HybridAgentNodeInner L117–198, L252–264](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/ui/src/components/topology/HybridTopologyNodes.tsx#L117-L198).

`ProgressiveTerminal` starts with a static preview, upgrades explicitly to live, and shares a cap that evicts the oldest live view back to static. It keeps agent lifetime separate from view lifetime. The terminal code uses xterm, maps native key/text input, and warns that CSS transform scaling breaks selection; font-size fitting preserves coordinates. Its own comments explicitly say this family has no chat/thread UI. LVX therefore still needs first-class human/provider conversations, peer-message history and turn/artifact detail alongside an optional terminal. Evidence: [ProgressiveTerminal L1–8, L56–100](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/ui/src/components/terminal/ProgressiveTerminal.tsx#L56-L100), [FocusedTerminal L1–38, L67–106, L157–163](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/packages/ui/src/components/terminal/FocusedTerminal.tsx#L157-L163).

The web UI is explicitly experimental, in maintenance mode, with best-effort support; CLI is primary. Native Windows is unsupported and WSL2 is the documented route, with no automated WSL2 tests claimed. This makes wholesale adoption a poor fit for a native Windows LVX feature. Keep the useful visual language and implement a platform adapter boundary. Evidence: [developing.md L50–54](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/docs/reference/developing.md#L50-L54), [README L38–45](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/README.md#L38-L45).

## Concrete integration recommendations

1. **Adapter contract:** implement `probeCapabilities`, `startConversation`, `runTurn`, `resume`, `interruptTurn`, `stopOwnedProcess`, and optional `fork`. Save provider-native ID, cwd, effective command/arguments, CLI version, requested model/effort, observed model when actually available, and generation. Do not map models or lower effort silently. Gemini support must be verified independently; report unavailable capability honestly.
2. **Prompt-preserving default:** launch the user's already authenticated native CLI with no generated AGENTS.md/CLAUDE.md, no synthetic system/main-agent prompt, no installed coordination plugin and no forced compaction. Append only the user's actual task or an explicitly addressed peer message. Keep provider defaults when no override was chosen. User-authored role material remains optional and visible.
3. **Mailbox and peer edges:** store message ID, full body/hash, sender/recipient node and generation, causal turn, delivery policy and state. Queue until idle by default; serialize one turn per native conversation. Use explicit from/to metadata in the delivered text. Reply/review links can be suggested without automatically broadcasting everything or creating loops. Apply bounded hop/routing controls visibly.
4. **Evidence-based state:** separate queued/admitted/started/completed/blocked from pending/written/delivered-unconfirmed transport and unreviewed/accepted/rejected quality. A zero CLI exit, delivery receipt or animated edge is never proof of accepted work. Keep full final text and artifact locations instead of a summary-only handoff.
5. **Reconnect and cancellation:** server owns sessions and append-only events; clients resume from sequence. Closing a node panel must not stop an agent. Cancel a queued turn without allowing a delayed write, interrupt a running turn explicitly, and bind stop to an expected session/generation. Never start fresh automatically after an ambiguous resume or retry unknown effects.
6. **Nexus-style UX:** use a draggable node canvas with compact provider/model/status cards, clearly different human/peer/route edges, selected-node conversation drawer, complete peer exchange history, inspectable launch settings, and optional terminal pane. Prefer ordinary conversation reading for most interaction; keep native terminal access for provider prompts and troubleshooting. Mark unsupported metrics unknown.
7. **Quality acceptance:** test identical tasks in the untouched native CLI and LVX with the same provider/model/effort, cwd snapshot and explicit task text. Compare launch/config differences first; then blinded task acceptance, code correctness, native tool use, retained context, full-output availability and recovery. Repeat across resume, human steering and peer handoff. Static OpenRig research cannot substitute for these runtime checks.
8. **Transport fixtures:** implement fake CLIs for partial output, Unicode/multiline content, delayed completion, permission/auth gate, cancelled-before-start, cancelled-after-write, missing/mismatched resume ID and unknown result after disconnect. Add a three-node collaboration test preserving exact peer text, plus manual native smoke checks only on installed authenticated providers. Do not claim a stub demonstrates native model quality.

## Licensing, limits and four-pass audit

The root license is [Apache License 2.0](https://github.com/mvschwarz/openrig/blob/9bb29d38819bdd2bbe5b8527ce057db606c82cf9/LICENSE). The inspected skills and bundled core plugin license files also declare Apache-2.0; the frontend-design skill contains its own Apache text. Conceptual reuse requires no copied runtime code. If code/assets are copied later, preserve applicable notices and review each copied component and its third-party dependencies separately. This report does not certify all 4,000+ checkout files or dependency licenses.

Four passes were completed: (1) implementation traced launch/session, message and UI paths from actual source; (2) expert reread separated native process identity from transcript/render evidence and quality; (3) refutation corrected the tempting but false assumptions that Gemini is built in, native CLI means untouched prompts, every outbox path is exactly-once, terminal receipts prove reasoning, or the web graph is a supported editable canvas; (4) polish replaced broad claims with pinned functions/line ranges and concrete LVX contracts. Remaining limits are explicit: no source suite execution, no live providers, no Windows/WSL runtime experiment, and no measured quality/performance conclusions. Leaf self-check validates artifact structure and source anchors; the parent must independently review depth before releasing the lease.
