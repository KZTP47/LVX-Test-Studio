# Agents on graphs and dashboards

Open **GitHub Actions**, **Workflows**, **Workflow details**, **Results**, or the reporting dashboard. In **Agents on this view**, choose a saved agent board and place one or more agents. Create agents and configure providers or working folders through **Create / manage agents**.

Click a character to open its conversation. Several conversations can stay open together; each has a dotted ownership line. Use the gear to set its name, color, embedded PNG/JPEG/WebP profile picture, assignment and roaming preference. Minimize or close a chat without stopping the agent. **Stop** requests cancellation for that agent. **Remove from this view** removes its character while keeping the agent and conversations on its saved board.

Choosing a profile picture now saves it immediately on the selected saved board, both in graph settings and in the agent board editor. A thumbnail and **Picture saved** status confirm the result. Removing a picture also saves immediately. These operations change only that agent's picture; unsaved instructions, goals, assignments and other settings stay as drafts. A brand-new board or unsaved agent still requires its first **Save board**, which the picture status explains. Pictures are embedded in SQLite and survive refresh, navigation and application restart without the original image file. Invalid images leave the prior saved picture intact, and a stale window reports a conflict instead of overwriting a newer picture. Pictures belong to an agent on its board; choosing another board selects that board's own profiles.

Drag an agent to move it within its assigned lane or canvas. Dropping saves its position and turns roaming off. Use **Resume roaming** beside the placement confirmation or in the chat to start it again; **Pause roaming** keeps it in place. The settings checkbox remains available too. A normal click still opens chat. Drag a conversation by its title bar, and drag any edge or corner to resize it. Position and size are saved independently for each agent and restored when you reopen the view. Selecting or focusing a conversation brings it to the front.

Press **Escape** during a drag or resize to cancel it. With an agent or conversation title focused, **Alt + arrow keys** move it. With the bottom-right resize grip focused, **arrow keys** resize the conversation; hold **Shift** for smaller increments. Windows stay within the viewport when it narrows. These layout changes use workspace SQLite configuration and create no JSON exports.

The character uses the exact user-supplied transparent octopus artwork, with profile pictures behind its central opening. Agent color tints the body while leaving the profile picture unchanged.

Use the square **Maximize conversation** button in a chat title bar to fill the app viewport. The same button restores its previous size and position. **Escape** also restores a maximized conversation. Drafts, history and scroll positions remain available; maximizing does not change saved normal window geometry.

Maximize shows the conversation and message composer, with settings hidden. Restore brings back the settings form with its edits and expanded/collapsed state intact. Opening the agent gear also restores the normal window before showing settings.

An imported-content trust error offers **bypass and accept** beside the warning. Clicking accepts only the imported items identified by that blocked action in the original workspace, then retries the action with its draft intact. Acceptance uses the existing imported-content trust records; it does not disable workspace trust or approve unrelated imports. Ordinary validation, save conflicts and provider errors do not offer this button.

When a saved chat cannot reconnect in the current project, the message box explains why in plain language and offers **Start new chat and send**. That explicit action creates a conversation for this agent’s current folder and sends the typed message with the current assignment. It preserves earlier conversations, which remain readable under **Earlier chats**. Opening a chat never starts or resends work automatically. A changed conversation in another window stops recovery and keeps the draft for review. Native identities from another project or installation are never reused.

Agents on the visual graph canvas and workflow details follow the graph currently open in that view, including when a saved graph is opened or renamed. The conversation context and assignment selector show **Current graph** and its name. Repository/workflow/job assignments on GitHub Actions remain exact and require reassignment if their target disappears. A suggestion from an earlier graph cannot be applied after switching graphs.

Assignments on GitHub Actions identify a repository, its independently selected YAML workflow, and optionally a job. Each message includes the current source snapshot. Switching or removing a workflow makes an earlier assignment unavailable until reassigned. Movement is cosmetic: assigning a repository does not change filesystem access or the agent's working directory. Native agents use the folders configured on their board; API agents have chat access only.

A completed assistant reply containing one complete fenced `yaml` workflow offers **Preview workflow draft**. Review the before/after source, then choose **Apply local draft**. The graph and repository draft update together, preserving original source for diff review. Open **Edit workflow & tests → Changes & publish** to publish separately. Partial responses, user messages, multiple YAML blocks, invalid graphs, changed assignments and stale source cannot silently replace a workflow.

On the visual workflow canvas, a completed assistant reply with a complete workflow object in one fenced `json` block offers **Preview graph draft**. LVX validates the graph and checks that its source snapshot is still current. Applying updates the visible draft and preserves Undo; Save and Run remain explicit actions. The graph table also supplies its current workflow as chat context; use the canvas or Tasks & graph review to apply graph changes there. Results and reporting supply actual test outcomes as context for discussion.

Chat and **Visible activity** show messages, public progress and recorded actions made available by the provider. They do not expose private model reasoning. Provider errors remain visible in conversation history and agent status; repair connections through the agent board.

User and assistant messages have separate chat bubbles. Appended view data appears beneath its related message in **Context sent with this message**, collapsed initially. Expand it to inspect the exact context that was supplied. This is a presentation split only: the stored message and provider input retain the complete original content. Expanded context stays open as the graph chat receives replies. Earlier chats use the same presentation.

**Visible activity** pulses only while a message is queued or the agent is working. Its summary includes elapsed time, and the expanded section shows public provider progress. **Technical details** separately contains recorded events for diagnosis. An elapsed clock means the request remains pending; it is not a provider heartbeat or proof that a remote service is healthy. Completion stops the pulse. Reduced-motion preferences suppress the pulse while retaining readable status and elapsed time.

Placement and roaming preferences are stored as revision-protected runtime configuration in the current workspace SQLite database. Profile changes use the existing canonical agent board, and conversation history uses the existing agent service. Each surface has its own placements. Loading a different saved board replaces that surface's placements. Multiple windows detect revision conflicts rather than overwriting another window's settings. No portable JSON save is created by this feature. Existing export actions retain the project's private-save rules.

Roaming travels between visible nodes in the assigned lane or canvas, with a subtle walking pose, ground shadow and **Visual roaming** proximity marker. This is cosmetic movement, not evidence that a node was edited, tested or inspected by the provider. Actual work appears in chat and Visible activity. Hovering or focusing the character pauses its next move; typing in a chat does not pause other agents. Reduced-motion preferences suppress travel and walking loops. Controls remain keyboard accessible. Agents outside the visible part of their assigned lane are hidden until that lane is visible again.

Board policy recommendation: keep each agent assigned to a board by default, with any future move to another board explicitly chosen by the user and carrying a clear destination/context preview. Automatic cross-board wandering would make task ownership and conversation context hard to follow. This update does not add cross-board migration. The existing current-graph behavior described above remains in place, and visual movement never grants access to another folder or project.

## Open-source research and integration

- [Tween.js](https://github.com/tweenjs/tween.js), MIT, version 25.0.0: reused directly for movement interpolation and easing. Bundled locally by the asset build, with its upstream license. Runtime does not fetch animation code from a CDN.
- [Agent Office](https://github.com/aaronlauhj/agent-office): reviewed the character/assignment/inspection interaction. LVX retains its own agent runtime, raster mascot, provider configuration and SQLite conversations. No Agent Office assets or source are copied.
- [Dagre](https://github.com/dagrejs/dagre): reviewed directed-graph layout as a possible alternative. The existing LVX workflow layout already handles the required fork/join lanes, so it remains in use.

Verification: `node --test tests/graph-companions.test.cjs` and `node scripts/workflow-companions-e2e.cjs`. The latter runs real Electron, IPC, SQLite and a labelled local HTTP provider fixture without paid requests. After `npm run build:desktop`, run it again with `--packaged` to verify the packaged source hashes and behavior.
